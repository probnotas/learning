<Article id="brief" title="The brief">

**Research question.** From joint-encoder data alone, which physical parameters of a series-elastic joint can a robot identify about itself, and how does the answer depend on the motion you command?

**Why a lab cares.** Humanoids like 1X's NEO are built around compliant, series-elastic actuation. Every self-model, world model or controller for them assumes something about effective stiffness, inertia and damping, and those drift when the robot picks something up, wears in, or gets damaged. A clean, reproducible identification study that also says *when identification fails* is exactly the kind of small, careful result that tells a team you can be trusted with their data.

**What you'll build.**
1. A compliant pendulum in **MuJoCo**: a position-controlled motor, a torsional spring, an arm and a bob.
2. A data pipeline: excite it, log encoder angles, difference to get $\dot\theta$ and $\ddot\theta$ (as you did in the lessons).
3. A least-squares self-model that recovers $[k/I,\ g/L,\ c/I]$, compared against MuJoCo's ground truth.
4. An **identifiability study**: excitation (none, single sine, multi-sine) × amplitude, measured by the condition number of $A^\top A$ and the parameter error.
5. A **body-change** experiment: mass ×1.5 mid-run, tracked with a sliding window.

**Deliverables.** A public GitHub repo (code, notebook, figures, README with one-command reproduction) and a 4-page paper written in the Paper item at the end of this project.

**Scope.** About 15 hours. Keep it small and rigorous rather than big and vague.

</Article>

**Starter model** (`pendulum.xml`). The arm is a child body of the rotor, so the arm joint's `stiffness` acts on the *relative* angle $\theta_a - \theta_m$, which is exactly series elasticity.

```xml
<mujoco model="compliant_pendulum">
  <option timestep="0.002" gravity="0 0 -9.81"/>
  <worldbody>
    <body name="rotor" pos="0 0 1.5">
      <joint name="motor" type="hinge" axis="0 1 0"/>
      <geom type="cylinder" size="0.04 0.02" euler="90 0 0" mass="0.2"/>
      <body name="arm">
        <joint name="spring" type="hinge" axis="0 1 0" stiffness="10" springref="0" damping="0.1"/>
        <geom type="capsule" fromto="0 0 0 0 0 -1" size="0.01" mass="0.001"/>
        <geom name="bob" type="sphere" pos="0 0 -1" size="0.04" mass="1"/>
      </body>
    </body>
  </worldbody>
  <actuator>
    <position name="theta_m" joint="motor" kp="400" kv="20"/>
  </actuator>
</mujoco>
```

**Minimal loop.** Joint angles are relative, so the arm's absolute angle is the sum.

```python
import mujoco, numpy as np
m = mujoco.MjModel.from_xml_path("pendulum.xml"); d = mujoco.MjData(m)
log = []
while d.time < 20:
    d.ctrl[0] = 0.3*np.sin(3*d.time) + 0.2*np.sin(7.3*d.time)   # multi-sine
    mujoco.mj_step(m, d)
    log.append((d.time, d.qpos[0], d.qpos[0] + d.qpos[1]))     # t, theta_m, theta_a
```

**Watch out for:**
- The bob's inertia isn't exactly $mL^2$: the sphere adds $\tfrac25 mr^2$ and the rod adds a little. Report the true $I$ from `m.body_inertia` and the composite inertia, not the textbook value.
- The motor only *tracks* $\theta_m$ through a PD loop. Log the actual `qpos[0]`, not the command.
- To bump the mass mid-run, scale `m.body_mass` **and** `m.body_inertia` of the arm body.
